# T005 — Caja negra de grabación y Cloudflare R2

**Objetivo:** grabar audio o video con audio, confirmar cada clip recibido y recuperar únicamente evidencia recibida con autorización propia.
**Arquitectura:** MediaRecorder en `/record`; API del mismo origen en Next; Worker de evidencias con binding privado R2. El Worker exige un secreto de servicio y una capacidad ciudadana por grabación. No depende de D1 ni Firebase.
**Stack:** Next 16.4.5, React 19.3, TypeScript estricto, Playwright, Wrangler 4.158.0 fijado (3.114.17 falló al abrir preview remoto).
**Especificación:** T5 de TASKS.md, DESIGN.md y PLANIFICACION.md.
**Dependencias:** T1 y T2 están [x]; hay shell, avatares y configuración Cloudflare. El bucket de AlzaVoz todavía no existe.
**Estado del plan:** cerrado; implementación y push verificados.

## Contexto y alcance

Ciudadano sin cuenta que necesita conservar evidencia durante una interrupción. Actualmente no existe captura ni API de evidencias. Se añade una ruta independiente enlazada desde Inicio; no se carga el grabador en la portada.
Los criterios de T5 exigen archivos reproducibles, recibos verificables, recuperación con permisos y estados honestos ante cierre, desconexión o permiso denegado.
Se admiten WebM VP8/Opus (video) y Opus (audio) cuando MediaRecorder declara soporte. Matriz inicial: Chromium de escritorio y emulación móvil; dispositivos físicos e iOS quedan fuera de la verificación y se explicitan.
No hay captura tras cerrar, cola persistente, cuenta ciudadana, publicación de denuncias ni despliegue final (T10).

## Brainstorming y decisiones

1. `start(3000)` continuo: menos pausas, pero sus blobs intermedios pueden no reproducirse solos; recuperar un sufijo sin cabecera no basta.
2. **Elegido:** cerrar un clip cada ~3000 ms y abrir el siguiente sobre el mismo MediaStream. Cada clip tiene contenedor completo; medimos inicio, fin y pausa real. No se promete continuidad sin huecos.
3. Remux/transcodificación: añade infraestructura y coste; no es necesaria para probar clips independientes.

API en Worker separado: usa R2 nativo sin fingir que `next start` recibe bindings. Next actúa como pasarela de origen único, sin exponer el secreto de servicio. Capacidad aleatoria de 256 bits por sesión; servidor guarda solamente su hash, con ID UUID. Leer y escribir requieren capacidad. Acceso de prueba durante siete días, subida durante una hora; límites de 100 clips, 2 MiB/clip y cola RAM de 16 MiB. El límite de cantidad acota una sesión a 200 MiB. Política remota de prueba: eliminar objetos a siete días mediante lifecycle del bucket.

La invocación de avanzar autoriza ejecutar decisiones rutinarias, pruebas y cierre. Se implementa en este checkout conservando los cambios previos. No se pide una aprobación redundante de diseño; se aplican brainstorming y grilling como auditoría del contrato específico del proyecto.

## Auditoría con /grill-me

| Caso | Riesgo | Decisión y prueba |
| --- | --- | --- |
| Cierre a mitad de clip | Último clip no finalizado | Solo listar recibos de R2. Cerrar pestaña con captura activa y recuperar con clave conservada. |
| Respuesta perdida tras PUT | Duplicación o falso pendiente | PUT condicional por índice; mismo hash y metadatos devuelve mismo recibo, otro contenido 409. |
| Dos PUT concurrentes | Sobrescribir evidencia | R2 onlyIf etagDoesNotMatch '*', comparar hash tras conflicto; prueba concurrente. |
| Red caída | RAM crece o éxito falso | Cola acotada, stop en límite; reintento explícito mientras pestaña viva, no borrar pendientes. |
| Dispositivo retirado / permiso tardío | Captura oculta o pistas vivas | Cancelación de solicitud y cleanup; pruebas de permiso denegado, captura interrumpida y navegación. |
| Robo/alteración de ID | Leer evidencia ajena | Secreto por sesión 256 bits; verificar hash antes de listar o descargar. Pruebas 401, otra sesión, caducidad y rutas inválidas. |
| Archivo inválido o enorme | Abuso de almacenamiento / XSS | Tamaño leído con límite, MIME permitido y firma EBML; bytes servidos attachment, nosniff y no-store. La validación profunda de codecs corresponde a T46. |
| No guardar clave | Pérdida de acceso al cerrar | Mostrar clave y explicar copia antes de grabar; sessionStorage solo ayuda en recarga. Sin recuperación mágica. |
| Servicio remoto inaccesible | Falsa integración | R2 local para suite repetible y R2 remoto privado de prueba para evidencia independiente. Registrar fallos reales. |

Contrato de clip: índice entero 0..99; MIME WebM permitido; inicio/fin en ms relativos al arranque, hash SHA-256 calculado por servidor, tamaño, receivedAt y etag. Metadatos y bytes en un único objeto R2 para que un recibo no preceda a la persistencia. Lectura de lista incluye customMetadata y orden por índice; sin manifiesto mutable que pueda perder actualizaciones.
