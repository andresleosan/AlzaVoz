# T009 — Bloque 5: Panel Privado de Gestión y Enlace Firebase Auth

> Plan de implementación para T9 en AlzaVoz.

**Objetivo:** Proporcionar al equipo legal y de asistencia de AlzaVoz un panel privado y protegido en `/admin` con autenticación Firebase Auth, validación criptográfica de tokens en servidor, gestión de expedientes y pistas en Cloudflare D1 con filtros multicriterio, acceso seguro a evidencias y clips en R2, actualización de estados de radicado, y un generador con IA (DeepSeek) de Derechos de Petición y Oficios Oficiales con obligatoriedad de revisión humana antes de cualquier uso.
**Arquitectura:** 
- Interfaz en `/admin` (estática en Cloudflare Pages `out/admin.html` y SSR/CSR en Next.js).
- Capa de autenticación Firebase Auth en cliente (`src/lib/admin/firebaseClient.ts`) y validación de tokens JWT RS256 en servidor Edge/Node (`src/lib/admin/auth.ts`).
- Endpoints de API en `/api/admin/[[...path]]` (Next.js App Router) y `functions/api/admin/[[path]].ts` (Cloudflare Pages Functions), unificados en `src/lib/admin/proxy.ts`.
- Módulo backend de administración en `workers/recordings/admin.ts` invocado desde `workers/recordings/index.ts` bajo el canal seguro `x-recording-gateway`.
- Persistencia en Cloudflare D1 (`confidential_reports`, `report_attachments`, `search_notices`, `search_tips`) y almacenamiento de objetos en Cloudflare R2 (`alzavoz-evidencias`).
- Generación de borradores legales con DeepSeek API (`deepseek-flash`) en la capa de servidor proxy, con plantilla estructurada de respaldo ante indisponibilidad de red/clave.
**Stack:** Next.js 16.4.5, React 19.3.0, TypeScript 5 (estricto, 0 `any`), Tailwind CSS v4, Web Crypto API (`crypto.subtle`), Cloudflare Workers/Pages Functions (Wrangler 4.158.0), Cloudflare D1, Cloudflare R2, Playwright 1.50.
**Especificación:** Tarea 9 de `TASKS.md`, `DESIGN.md`, `PLANIFICACION.md`.
**Dependencias:** T5 (Caja negra R2) y T6 (Denuncia confidencial D1), ambas completadas y verificadas.
**Estado del plan:** cerrado; código implementado, probado y verificado.

## Contexto y alcance

### Problema, persona usuaria y escenario de uso
AlzaVoz permite a la ciudadanía radicar denuncias confidenciales anónimas (`/report`) identificadas con códigos `ALZ-YYYY-XXXXXX`, adjuntando fotos higienizadas, audios con voz transformada, y sesiones de grabación en caliente (`/record`). Asimismo, permite publicar avisos de búsqueda de personas y mascotas (`/search`) y recibir pistas anónimas.
Hasta ahora, la consulta de cada caso era exclusiva del ciudadano portador de la clave secreta de expediente. Sin embargo, el equipo de acompañamiento legal y derechos humanos del Concejal y defensores ciudadanos requiere una consola centralizada para:
1. Auditar los casos radicados en las 16 comunas y 5 corregimientos de Medellín.
2. Filtrar ágilmente por nivel de riesgo (`alto`, `medio`, `bajo`), categoría legal, estado y comuna.
3. Visualizar y descargar de forma segura las evidencias adjuntas y clips de grabación en R2 sin exponer enlaces públicos permanentes.
4. Cambiar el estado del expediente (`radicado` -> `en_revision` -> `en_tramite` -> `oficio_tramitado` -> `archivado`) y registrar notas internas de gestión.
5. Redactar borradores formales de *Derechos de Petición* (Art. 23 C.P.) y *Oficios Oficiales de Solicitud de Información* dirigidos a las autoridades competentes (Secretaría de Movilidad, MEVAL / Policía, ICBF, Fiscalía, Personería Distrital).
6. Supervisar avisos comunitarios y pistas anónimas recibidas.

### Comportamiento actual inspeccionado y límites de esta entrega
- No existía panel de administración en `/admin`.
- Las denuncias solo podían consultarse individualmente pasando la clave privada del ciudadano por `Authorization: Bearer <secret>`.
- Las evidencias R2 no tenían ruta de consulta administrativa autorizada.
- Esta entrega construye la autenticación completa con Firebase Auth, validación criptográfica de tokens en servidor, filtros, visor de evidencias, actualización de estados y generación de borradores con revisión humana obligatoria.
- Límites: El sistema NO envía automáticamente los oficios ni correos a las entidades gubernamentales (requiere descarga/copia y trámite humano por canales oficiales de radicación de cada entidad). No se altera el anonimato ciudadano hacia terceros externos.

## Brainstorming y decisiones

1. **Autenticación con Firebase Auth en arquitectura Edge/Pages:**
   - *Alternativa 1:* Usar el SDK oficial de Node `firebase-admin`.
     - *Inconveniente:* Incompatible con Cloudflare Workers / Pages Functions (depende de módulos nativos de Node, gRPC y supera los 50MB).
   - *Alternativa 2 (Elegida):* Validación de tokens ID de Firebase mediante Web Crypto estándar (`crypto.subtle`).
     - Un token ID de Firebase es un JWT firmado con RS256 por Google. En producción se obtienen las claves públicas oficiales de Google (`https://www.googleapis.com/service_accounts/v1/jwk/securetoken@system.gserviceaccount.com`), verificando `iss`, `aud`, `exp`, `sub`.
     - Para tests E2E y entornos aislados offline, el validador admite generación y comprobación de claves RS256 sintéticas locales con Web Crypto, asegurando pruebas 100% deterministas de tokens expirados, firmas manipuladas, auditoría y claims inválidos.
   - *Cliente Firebase:* Componente de interfaz desacoplado con soporte para inicio de sesión seguro (Email/Password y tokens de sesión), manejo de estado de sesión, expiración y cierre de sesión.

2. **Gestión de casos y filtros en D1:**
   - La tabla `confidential_reports` ya almacena `code`, `category`, `risk_level`, `commune`, `neighborhood_reference`, `summary`, `incident_date`, `recording_session_id`, `recording_clip_count`, `attachment_count`, `status`, `created_at`.
   - Añadimos soporte para `admin_notes` y `updated_at`.
   - El endpoint `GET /api/admin/reports` soporta parámetros de consulta:
     - `commune`: nombre o reserva.
     - `riskLevel`: `alto` | `medio` | `bajo`.
     - `category`: categorías vigentes de `REPORT_CATEGORIES`.
     - `status`: `radicado` | `en_revision` | `en_tramite` | `oficio_tramitado` | `archivado`.
     - `search`: búsqueda textual insensible a mayúsculas en `code`, `summary`, `neighborhood_reference`.
   - El endpoint `PATCH /api/admin/reports/:code` permite actualizar `status` y `adminNotes` con validación estricta de valores permitidos.

3. **Acceso controlado a evidencias R2:**
   - Endpoint `GET /api/admin/reports/:code/attachments/:slot`:
     - Valida la sesión del administrador.
     - Verifica que el expediente exista en D1 y que el adjunto pertenezca efectivamente a dicho expediente.
     - Extrae la clave canónica en R2 (`reports/${code}/${slotIndex}`) y transmite los bytes con cabeceras seguras (`X-Content-Type-Options: nosniff`, `Content-Disposition`, `X-Content-SHA256`).
     - Rechaza llamadas para expedientes inexistentes o adjuntos ajenos (404/403).
   - Endpoint `GET /api/admin/reports/:code/recordings/:clipIndex`:
     - Si el expediente tiene `recording_session_id`, valida el índice y entrega el clip WebM desde R2 (`recordings/${sessionId}/clips/...`).

4. **Borradores con IA (DeepSeek) y revisión humana obligatoria:**
   - El endpoint `POST /api/admin/drafts` recibe el código del expediente, la entidad destinataria elegida (`movilidad`, `meval`, `icbf`, `fiscalia`, `personeria`) y el tipo de documento (`derecho_peticion` u `oficio_informacion`).
   - Se procesa en servidor con `DEEPSEEK_API_KEY`. En caso de falta de clave o indisponibilidad de red externa, se activa un generador de plantilla jurídica exhaustiva basada en la legislación colombiana (Ley 1755 de 2015, Ley 1801 de 2016, Ley 769 de 2002, Ley 1257 de 2008, Ley 1098 de 2006).
   - El documento generado incluye obligatoriamente:
     - Encabezado con advertencia indeleble: `BORRADOR SUJETO A REVISIÓN HUMANA OBLIGATORIA. Este documento NO ha sido radicado ni sustituye la asesoría de un abogado titulado.`
     - Hechos cronológicos fundamentados en la denuncia.
     - Pretensiones / Peticiones numeradas.
     - Fundamento de derecho colombiano.
     - Anexos con el recuento de evidencias peritadas.
     - Campos pendientes entre corchetes para rellenar por el operador: `[NOMBRE Y CÉDULA DEL SOLICITANTE]`, `[CORREO ELECTRÓNICO PARA NOTIFICACIONES]`, `[DIRECCIÓN FÍSICA]`, `[FIRMA DIGITAL O AUTÓGRAFA]`.
   - La interfaz no dispone de ningún botón de "Envío automático a la entidad"; únicamente permite copiar el texto al portapapeles o descargarlo en archivo `.txt` / `.md`.

## Auditoría con grilling

| Supuesto o caso límite específico | Riesgo para la persona o el sistema | Decisión, mitigación y cómo comprobarla |
| --- | --- | --- |
| Token JWT ausente en llamada a `/api/admin/*` | Acceso no autorizado a datos confidenciales de ciudadanos. | El servidor rechaza con 401 Unauthorized inmediatamente sin consultar D1 ni R2. Comprobado con llamadas fetch sin cabecera de autorización. |
| Token JWT con firma alterada, expirado o con `aud`/`iss` incorrecto | Suplantación de identidad del equipo legal. | Validación estricta con Web Crypto: comprobación de `exp < now`, `iss === securetoken.google.com/alzavoz-3e805`, `aud === alzavoz-3e805` y firma criptográfica. Si falla cualquier check -> 401. |
| Intento de descargar un adjunto de un caso inexistente o que no pertenece al expediente | Fuga de información cruzada entre expedientes. | El backend en D1 valida la relación estricta entre `report_code` y `slot_index`. Si no hay coincidencia, retorna 404 Not Found. |
| Intento de llamada directa a los endpoints de administración en el Worker sin pasar por el Gateway | Bypass de la autenticación del proxy. | El Worker exige cabecera `x-recording-gateway` coincidente con `GATEWAY_SECRET`. Sin ella retorna 401. |
| La IA alucina datos personales no suministrados por el ciudadano o genera órdenes falsas | Presentación de información incorrecta ante autoridades judiciales o administrativas. | El prompt exige limitarse estrictamente a los hechos narrados; todos los datos faltantes se marcan con `[PENDIENTE: ...]`; se incluye banner de advertencia obligatorio y no existe envío automático. |
| Desconexión o fallo de la API de DeepSeek | Bloqueo de la gestión jurídica del equipo. | Fallback local determinista: genera el Derecho de Petición u Oficio con estructura jurídica completa, hechos del caso y artículos de ley colombiana. |
| Intentos de inyección SQL o de parámetros en filtros de búsqueda | Corrupción de consultas D1 o exposición masiva. | Consultas SQL estrictamente parametrizadas con `bind(...)` y validación de tipos enum en contratos TypeScript. |
