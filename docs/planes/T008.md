# T008 — Tableros de búsqueda y afiches con QR

**Objetivo:** crear y consultar cuatro tipos de aviso, descargar afiches con QR y aportar pistas privadas sin cuenta.
**Arquitectura:** `/search` estático con consulta por `?id=UUID`; Pages Functions y Next comparten gateway hacia Worker privado con D1. La IA se ejecuta en Pages/Next, donde ya existe la clave DeepSeek, sobre datos públicos únicamente.
**Stack:** Next 16.4.5, React 19.3, TypeScript estricto, Wrangler 4.158.0, D1, Canvas y biblioteca QR cargada al descargar.
**Especificación:** T8 de TASKS.md, DESIGN.md, PLANIFICACION.md. Dependencia T6 completada y verificada en T006.
**Estado:** cerrado; código enviado y despliegues comprobados.

## Contexto y alcance

No existe módulo de búsqueda. Se reutiliza el patrón community (gateway, binding RECORDINGS y D1); no se mezclan avisos con denuncias confidenciales. Cuatro categorías: persona perdida/encontrada y mascota perdida/encontrada. No se requieren fotos para cumplir T8; el afiche textual incluye descripción autorizada y QR. Sin reconocimiento facial ni identificación automática. Moderación y caducidad completa pertenecen a tareas posteriores; advertir que los avisos no están verificados.

## Brainstorming y decisiones

- Alternativas: almacenamiento solo local no satisface consulta compartida; servicio nuevo duplica infraestructura; D1 existente permite persistencia y separación explícita público/privado. Se elige D1.
- Identificadores UUID opacos. `requestId` privado de reintento separado del UUID público generado por el servidor: evita que el id público se use para probar contactos por diferencias entre éxito y 409. Campos públicos: tipo, título breve, descripción, comuna, fecha del suceso y fecha de creación. Contacto opcional del autor y texto/contacto de pistas nunca salen en respuestas públicas.
- Consentimiento explícito antes de publicar, vista de revisión, aviso de no incluir documentos, teléfonos, direcciones precisas ni datos sensibles en campos públicos. Las publicaciones pueden copiarse fuera de AlzaVoz.
- Pistas sin identidad obligatoria. Explicar que se almacenan para revisión del equipo, cuyo panel llega en T9; no prometer seguimiento ni respuesta inmediata.
- Coincidencias solo a solicitud: comparar avisos de categorías complementarias con candidatos acotados; consentimiento para enviar campos públicos a DeepSeek; ausencia de clave o fallo muestra indisponibilidad, nunca una identificación inventada. Respuesta de IA validada contra IDs candidatos y etiquetada como sugerencia.
- `/avanzar` autoriza implementación y cierre; elecciones rutinarias resueltas con el contrato, sin decisiones imprescindibles abiertas.

## Auditoría con grilling

| Caso | Decisión y prueba |
| --- | --- |
| Se pierde respuesta de publicación/pista | UUID idempotente conservado al reintentar; payload diferente con mismo ID produce 409. |
| Intento de leer pistas o contacto | Proyección pública explícita, sin endpoint público de pistas; pruebas con secretos centinela. |
| Entradas no confiables | Límites de bytes y campos, claves permitidas, UUID/fecha/comuna/tipo validados; SQL parametrizado, texto React/Canvas, origen y cabecera propios en mutaciones. |
| Aviso inexistente, red caída | Error claro y reintento sin afirmar éxito. Pista a aviso inexistente rechazada. |
| IA alucina ID o sigue instrucciones del aviso | Salida estructurada validada y acotada a candidatos complementarios; sin candidatos no llamar modelo. Probar no coincidencia, error y respuesta malformada. |
| QR se descarga pero no apunta al aviso | Decodificar PNG descargado en E2E, contrastar URL y abrirla. |
| Publicación sensible | Datos mínimos, consentimiento y advertencias; no prometer moderación, anonimato absoluto ni resolución. |
