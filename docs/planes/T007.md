# T007 — Convivencia y Alerta Barrial (Sonómetro Web)

**Objetivo:** observar 15 segundos de señal acústica y compartir voluntariamente una observación por comuna y categoría, sin audio ni coordenadas individuales.
**Arquitectura:** AudioWorklet local → resumen en RAM; formulario explícito → Pages/Next → Worker privado → D1; consulta pública exclusivamente agregada.
**Stack:** Next 16.4.5, React 19.3, TypeScript, Web Audio, Cloudflare D1 y Playwright existentes; sin dependencias nuevas.
**Especificación:** T7 de TASKS.md, DESIGN.md, PLANIFICACION.md. Dependencias T1/T2 completadas.
**Estado:** completada, enviada y desplegada. Código 0a06050; verificación de producción del 7 de noviembre de 2026 (Bogotá). Ejecución directa en main, conservando trabajo previo.

## Contexto y alcance
El inicio anuncia un radar aún no disponible. Se añade /community con observación local y mapa esquemático de las 16 comunas existentes. No se atribuyen barrios específicos a una comuna seleccionada, ni se consulta GPS. No se incorporan búsquedas (T8), certificación, denuncia automática, rankings de ruido ni umbrales jurídicos.

## Brainstorming y decisiones
- Se descarta convertir dBFS a dB SPL mediante una constante inventada. Se muestra RMS digital, sin ponderación A, referencia 1 y estado «Sin calibración».
- Se elige AudioWorklet con conteo continuo de muestras frente a ventanas aisladas de AnalyserNode por temporizador: duración exacta de 15 s de muestras, progreso limitado a 4 actualizaciones/s, sin enviar PCM al hilo principal.
- Comparación física futura: mismo micrófono, ganancia y orientación, fuente estable, sonómetro/calibrador trazable, varios niveles/frecuencias, comparación antes/después y registro de incertidumbre. No hay hardware de referencia en esta sesión; pruebas sintéticas validan cálculo, no presión acústica.
- Se reutiliza D1 y el gateway privado; frente a mapa externo se elige SVG local con centros aproximados de comunas, leyenda y tabla accesible. No requiere proveedor de mapas ni comunica ubicación a terceros.
- Solo se envían requestId aleatorio, comuna, categoría y día de Bogotá. Reintento idempotente; sin audio, dBFS, identificadores de dispositivo, relato, dirección o coordenadas. Agregados de últimos 30 días, sin IDs ni fechas individuales. Observaciones no verificadas, no personas distintas.
- Decisiones rutinarias resueltas con contexto; no quedan preguntas indispensables.

## Auditoría con grilling
| Caso | Riesgo | Decisión y prueba |
| --- | --- | --- |
| Permiso denegado/tardío, sin micrófono | Captura accidental o espera infinita | Cancelación con AbortSignal; detener pistas que lleguen tarde; error claro y reintento. |
| Pestaña oculta, pista terminada o contexto suspendido | Resultado parcial presentado como 15 s | Abortar y descartar; prueba de interrupciones. |
| Silencio/clipping | Interpretación engañosa | Silencio sin -Infinity; alerta de saturación; seno conocido y silencio en pruebas. |
| Reintento tras perder respuesta | Conteo duplicado | UUID único; mismo contenido admite reintento, contenido distinto 409. |
| Entrada extra/inyección/origen ajeno | Filtrar datos personales o alterar SQL | Allowlist estricta, 512 bytes, SQL enlazado, validación de origen, gateway privado y límite global existente. |
| API caída | Mapa vacío confundido con cero | Error separado, reintentar; borrador en RAM. |
| Recuentos pequeños/abuso | Inferencia o falsas conclusiones | Solo comuna y categoría a 30 días; no tiempo individual; observaciones no verificadas, no mapa acústico. Umbrales de publicación completos quedan en T58. |
